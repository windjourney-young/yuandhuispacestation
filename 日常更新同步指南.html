日常更新同步指南

每次改完代码或图片后，如何把更新推送到 GitHub Pages · 三种方法任选

一句话总览

无论你改了什么，本质都是：把项目根目录 E:/App/love/ 下的文件同步到 GitHub 仓库，GitHub Pages 会在 1-2 分钟内自动重新部署，刷新域名即可看到更新。

三种方法适用场景：

  • 方法 A（命令行 Git）—— 最快、最专业，适合装了 Git 的人
  • 方法 B（GitHub 网页拖拽）—— 不用装任何软件，适合偶尔更新一两张图
  • 方法 C（重新打包上传）—— 适合大批量改动或不熟悉 Git 的人

一、更新流程概览（4 步）

1
本地改动
改代码 / 加图片
2
生成清单
加图后跑一次脚本
3
推送到 GitHub
用下面 A/B/C 任一方法
4
刷新验证
等 1-2 分钟看域名
关键提醒：只要你增减了 images/ 文件夹里的图片，就必须先运行 tools/gen_album_manifest.py 重新生成清单，再推送。否则网页上的相册不会变。

二、准备工作：搞清楚你的仓库地址

下面所有方法都会用到这两个信息，先去 GitHub 把它们找出来：

  • 你的GitHub用户名—— 登录 GitHub 后右上角头像旁显示的名字
  • 你的仓库名—— 你上传网站时建的仓库（很可能就是 yuandhuispacestation）

你的仓库完整地址就是：https://github.com/你的GitHub用户名/你的仓库名

网站访问地址：https://你的GitHub用户名.github.io/你的仓库名/（或你绑定的自定义域名）

方法 A：命令行 Git（推荐，最快）

适合：装了 Git 的人 · 改任何内容都适用
前置条件：电脑上要装 Git。Windows 安装包下载：https://git-scm.com/download/win，一路下一步即可。装完后右键文件夹能看到 "Open Git Bash here" 或 "Git Bash Here" 选项就说明装好了。

第一次使用：把仓库克隆到本地（只需做一次）

如果你之前是直接在 GitHub 网页上传的（项目根目录没有 .git 文件夹），需要先做一次"克隆"建立关联：

1

在 GitHub 你的仓库页面，点击绿色的 Code 按钮，选 HTTPS，复制地址（类似 https://github.com/你的GitHub用户名/你的仓库名.git）。

2

把项目根目录 E:/App/love/ 里现有的所有文件临时移到别处（比如桌面新建一个文件夹放着）—— 因为下一步要克隆，会跟现有文件冲突。

3

在 E:/App/ 目录下右键 → Git Bash Here，执行：

# 把 username/repository 换成你的真实用户名和仓库名
git clone https://github.com/你的GitHub用户名/你的仓库名.git love

这会在 E:/App/love/ 创建一个与 GitHub 关联的本地仓库（包含线上的所有文件）。

4

把你刚才移走的所有文件覆盖回 E:/App/love/（保留新克隆出来的 .git 文件夹不要删）。这样本地就是最新的代码 + GitHub 关联。

以后就再也不用做这一步了。

日常更新：每次改完东西后

在 E:/App/love/ 目录下右键 → Git Bash Here，依次执行下面 4 条命令：

# 1. 加图后先生成相册清单（没动图片可跳过这步）
python tools/gen_album_manifest.py

# 2. 进入项目目录（如果还没在里面）
#    Git Bash 已经在 love 目录就不用 cd

# 3. 把所有改动加入暂存区
git add -A

# 4. 提交一个版本（引号里是说明，可随意改）
git commit -m "更新相册图片与太阳系视图"

# 5. 推送到 GitHub
git push
推送成功后：打开你的域名，等 1-2 分钟，刷新即可看到更新。GitHub Pages 偶尔有缓存，可按 Ctrl + F5 强制刷新。
第一次 git push 时：可能弹出登录窗口，按提示登录 GitHub 即可。如果用 token 登录，去 GitHub → Settings → Developer settings → Personal access tokens 生成一个有 repo 权限的 token 当密码用。

方法 B：GitHub 网页拖拽上传（不用装软件）

适合：偶尔更新一两张图 / 改个文字 · 不装任何软件
1

在本地改完文件后，如果动了 images/ 文件夹，记得先双击运行 tools/gen_album_manifest.py 重新生成 js/album-manifest.js。

2

浏览器打开你的仓库：https://github.com/你的GitHub用户名/你的仓库名

3

更新已有文件（如 index.html、style.css、js/main.js、js/album-manifest.js）：

  • 在仓库页面点击对应文件名进入文件详情页
  • 点右上角铅笔图标 ✏ Edit this file
  • 清空原有内容，把本地文件内容复制粘贴进去
  • 滚动到底部，在 "Commit changes" 填写说明（如"更新首页"），点 Commit changes 绿色按钮
4

新增图片文件（往 images/ 加图）：

  • 在仓库页面点击进入 images 文件夹（如果没有就点 Add file → Create new file，在名字框输入 images/.gitkeep 创建目录）
  • 进入 images 文件夹后，点 Add file → Upload files
  • 把图片直接拖到虚线框里，或点击选择文件
  • 等上传完成，滚动到底部点 Commit changes
注意：GitHub 网页单次上传限制约 25 MB / 100 个文件。图片太多或太大请用方法 A 或 C。

方法 C：整包重新上传（适合大批量改动）

适合：一次性改了很多文件 · 不想用 Git 命令
1

本地改完后，跑一次 tools/gen_album_manifest.py（动了图片的话）。

2

进入 E:/App/love/，选中要上传的所有文件和文件夹（index.html、style.css、js/、images/，不要选 .git、_github_pkg、部署上线指南.html、日常更新同步指南.html、项目需求.txt、.workbuddy），右键压缩成 zip。

3

解压这个 zip 看一眼，确认结构是：index.html 在最外层，js/、images/、tools/ 是同级文件夹。

4

打开 GitHub 仓库页面 → 点 Add file → Upload files，把解压后的所有文件（不是 zip 包本身）拖进去上传。

如果同名文件已存在，GitHub 会自动覆盖。

5

底部填说明，点 Commit changes。

三、常见更新场景速查

场景 1：往相册加几张新图

  1. 把图片放进 E:/App/love/images/
  2. 双击运行 tools/gen_album_manifest.py（看到"图片数量：N"即成功）
  3. 用方法 A/B/C 把 images/ 文件夹（含新图）和 js/album-manifest.js 推送到 GitHub
  4. 刷新域名，看相册

场景 2：从相册删除某张图

  1. 从 images/ 删除对应图片文件
  2. 运行 tools/gen_album_manifest.py
  3. 推送 images/ 和 js/album-manifest.js 到 GitHub
  4. 如果用方法 B，还要去 GitHub 仓库的 images 文件夹里把那张图也删掉（点文件 → 右上角垃圾桶图标 → Commit）

场景 3：改了首页文字 / 样式 / JS 逻辑

  1. 本地修改 index.html / style.css / js/*.js
  2. 不用跑脚本（除非动了 images/）
  3. 用方法 A/B/C 把改动文件推送到 GitHub
  4. 刷新域名验证

场景 4：换了一整套图片

  1. 清空 images/ 里的旧图（保留 README.txt）
  2. 把新图全部放进 images/
  3. 运行 tools/gen_album_manifest.py
  4. 推送 images/ 和 js/album-manifest.js 到 GitHub
  5. 如果用方法 B，记得去 GitHub 仓库手动删掉旧的图片文件

四、常见问题

Q1：推送后刷新网站没变化？

排查：

  • GitHub Pages 部署需要 1-2 分钟，等一下再刷新
  • 浏览器有缓存，按 Ctrl + F5（Mac 是 Cmd + Shift + R）强制刷新
  • 去 GitHub 仓库 → Settings → Pages，看顶部是否显示 "Latest deployment green ✓"
  • 如果显示部署失败，去仓库 → Actions 标签看具体报错

Q2：git push 报错 "rejected" 或 "non-fast-forward"？

原因：你在 GitHub 网页改过东西，本地不知道。

解决：先执行 git pull 拉取远程最新，再 git push。如果 pull 时报冲突，按提示解决冲突再提交。

Q3：git push 提示要密码但输了 GitHub 密码不对？

GitHub 早已不支持密码登录 Git。需要用 Personal Access Token 当密码：

  1. GitHub → 右上角头像 → Settings → Developer settings → Personal access tokens → Tokens (classic)
  2. 点 Generate new token，勾选 repo 权限，生成
  3. 复制 token（只显示一次！），git push 时把它当密码粘进去
  4. 勾选"记住密码"后下次就不用再输了

Q4：图片在网页上显示裂图？

排查：

  • 确认图片确实推送到 GitHub 仓库的 images 文件夹了
  • 确认 js/album-manifest.js 里的路径跟实际文件名一致（大小写敏感）
  • 图片名避免中文、空格、特殊字符，用英文+数字最稳
  • 直接打开 https://你的域名/images/文件名 看能不能访问

Q5：我能不能不每次都跑那个 Python 脚本？

可以，但代价是：

  • 需要手动编辑 js/album-manifest.js，按格式新增/删除一行图片路径
  • 容易漏写、写错路径，导致相册裂图

建议还是用脚本，一秒搞定不出错。Python 双击就能运行，Windows 装了 Python 都能直接跑。

Q6：images/ 文件夹太大，GitHub 能放下吗？

单个 GitHub 仓库建议不超过 1 GB，单个文件不超过 100 MB（图片一般远小于此）。如果你的相册图片很多（几百张），建议：

  • 用工具把图片压缩到合理尺寸（如 1600px 宽以内，质量 85%）
  • 或把图片托管在别的图床（阿里云 OSS、七牛云等），把外链填到 js/album-manifest.js 里手动维护

Q7：能不能让相册自动识别新图片，不用跑脚本？

不能。GitHub Pages 是纯静态托管，没有服务端，网页无法在运行时扫描服务器文件夹。必须用脚本在本地提前生成清单文件，让网页加载清单。
这是静态网站的固有约束，所有 GitHub Pages 站点都这样。
